# راهنمای انتقال و نصب پایگاه داده VamCity

## وضعیت فعلی

- ساختار سه بکاپ SQL Server استخراج شده است.
- بسته ساختار MariaDB 10.6 روی نمونه آزمایشی نصب و اعتبارسنجی شده است.
- ابزار انتقال جریانی PHP نوشته شده و اجرای `--dry-run` روی سرور موفق بوده است.
- هنوز هیچ رکوردی به پایگاه مقصد وارد نشده و دیتابیس‌های اصلی SQL Server دست‌نخورده‌اند.

## پایگاه‌های مقصد

| منبع SQL Server | مقصد |
|---|---|
| `vamcityc_vamcity_import_20261028` | `vamcitydigibilepay` |
| `vamcityc_bluvamdb_import_20261028` | `vamcitydigibilepay_bluvamdb` |
| `vamcityc_transferDb_import_20261028` | `vamcitydigibilepay_transferdb` |

دیتابیس اصلی همان نام درخواستی `vamcitydigibilepay` را دارد. دو پایگاه جانبی جدا نگه داشته شده‌اند تا جدول‌های هم‌نام و اتصال‌های مستقل سامانه با یکدیگر مخلوط نشوند.

## نصب در DirectAdmin یا cPanel

1. سه پایگاه بالا را از بخش MySQL Management بسازید. در cPanel/DirectAdmin ممکن است نام کاربری هاست به ابتدای نام پایگاه اضافه شود.
2. یک کاربر MySQL بسازید و به هر سه پایگاه دسترسی کامل بدهید.
3. فایل `database/migration/config.example.php` را به `database/migration/config.php` کپی کنید.
4. نام واقعی پایگاه‌ها، نام کاربر و گذرواژه را در `config.php` وارد کنید. این فایل در `.gitignore` است و نباید در GitHub بارگذاری شود.
5. اگر ابزار انتقال روی همان سرور دارای SQL Server اجرا می‌شود، ابتدا دستور زیر را اجرا کنید:

```bash
php database/migration/migrate.php --dry-run
```

6. فقط پس از تأیید دسترسی و نام پایگاه‌ها، انتقال واقعی را اجرا کنید:

```bash
php database/migration/migrate.php --execute
```

ابزار در صورت خالی بودن پایگاه مقصد، ساختار مربوط را نصب می‌کند. اگر ساختار از قبل نصب شده باشد، آن را بررسی و ادامه می‌دهد. برای جلوگیری از ورود تکراری، وضعیت هر جدول و تعداد رکوردهای انتقال‌یافته ثبت می‌شود؛ اجرای دوباره پس از قطع‌شدن از آخرین نقطه ادامه می‌دهد.

## نصب دستی ساختار از phpMyAdmin

اگر فقط ساختار را می‌خواهید وارد کنید:

- فایل `database/mysql/schema-main.sql` را پس از انتخاب پایگاه اصلی وارد کنید.
- فایل `database/mysql/schema-bluvamdb.sql` را در پایگاه جانبی BlueVam وارد کنید.
- فایل `database/mysql/schema-transfer.sql` را در پایگاه انتقال وجه وارد کنید.

فایل یکپارچه `database/mysql/schema.sql` هر سه پایگاه را می‌سازد و به مجوز CREATE DATABASE نیاز دارد؛ برای حساب‌های محدود DirectAdmin/cPanel، سه فایل تفکیک‌شده مناسب‌ترند.

## حفظ اطلاعات و تفاوت‌های فنی

- داده‌ها مستقیماً از SQL Server به MariaDB منتقل می‌شوند؛ فایل داده حاوی اطلاعات مشتریان در مخزن عمومی ساخته نمی‌شود.
- اعداد اعشاری و شناسه‌های بزرگ در مسیر انتقال به رشته تبدیل می‌شوند تا دقت آن‌ها در PHP از بین نرود.
- مقدار دقیق زمان‌های SQL Server در ستون‌های کمکی `__raw_...` نگهداری می‌شود؛ ستون زمانی MariaDB برای عملیات معمول قابل استفاده است.
- نام جدول‌های schemaهای غیر از `dbo` به شکل `<schema>__<table>` نگاشت می‌شود.
- ایندکس‌های فیلترشده و ستون‌های INCLUDE به نزدیک‌ترین ساختار قابل پشتیبانی در MariaDB تبدیل شده‌اند؛ این بخش کاملاً همسان با SQL Server نیست.
- هر سه دیتابیس مبدأ از `SQL_Latin1_General_CP1_CI_AS` استفاده می‌کنند. MariaDB 10.6 روی سرور collation متناظرِ case-insensitive/accent-sensitive از خانواده `utf8mb4_*_as_ci` ندارد. ساختار فعلی از `utf8mb4_unicode_ci` استفاده می‌کند که accent-insensitive است؛ بنابراین رفتار جست‌وجو و یکتایی متنی در این بخش عیناً یکسان نیست. برای نزدیک‌تر شدن به رفتار مبدأ، MySQL 8 با `utf8mb4_0900_as_ci` یا راهکار مقایسه سفارشی قابل بررسی است.

## پیش‌نیاز اجرای انتقال واقعی

کاربر SSH مورد استفاده GitHub Actions دسترسی مدیریتی MariaDB ندارد. برای همین اجرای آزمایشی فقط خواندنی بوده است. اجرای `--execute` به نام کاربری و گذرواژه MySQL دارای دسترسی کامل به سه پایگاه مقصد نیاز دارد.

همچنین اندازه فایل‌های مبدأ حدود 859MB و فضای آزاد سرور حدود 2.1GB (مصرف دیسک 98%) است. پیش از انتقال واقعی باید چند گیگابایت فضای آزاد اضافی فراهم شود؛ فایل داده موقت ساخته نمی‌شود، اما خود پایگاه‌های MariaDB و ایندکس‌ها به فضای دیسک نیاز دارند.
