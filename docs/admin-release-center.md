# مرکز نسخه‌ها و بروزرسانی دیجی‌بایل

## رفتار

- نسخه نصب‌شده از `DEPLOY_COMMIT_SHA` و `APP_VERSION` در محیط برنامه خوانده می‌شود.
- آخرین commit شاخه `main` و آخرین اجرای گردش استقرار از GitHub خوانده می‌شود.
- شروع استقرار فقط از نشست مدیر ارشد مجاز است.
- درخواست استقرار فقط گردش موجود `.github/workflows/deploy-digebail-server.yml` را برای شاخه `main` اجرا می‌کند؛ برنامه روی سرور مستقیماً `git pull` یا shell command اجرا نمی‌کند.
- درخواست تکراری در زمان اجرای استقرار فعال رد می‌شود.
- رویداد درخواست انتشار در جدول `admin_release_events` پایگاه PostgreSQL ثبت می‌شود.
- این قابلیت هیچ جدول مشتری، پرونده یا داده عملیاتی را حذف یا بازنویسی نمی‌کند و migration مخرب اجرا نمی‌کند.

## تنظیم یک‌باره اتصال

در GitHub مخزن `digibile/digibail` به مسیر Settings → Secrets and variables → Actions بروید و یک Repository secret با نام دقیق `GITHUB_DEPLOY_TOKEN` بسازید.

توکن باید Fine-grained و فقط برای همین مخزن باشد و این مجوزها را داشته باشد:
- Actions: Read and write
- Contents: Read-only

پس از ذخیره secret، یک بار گردش `Deploy digebail.ir production site` را از شاخه `main` اجرا کنید. گردش، توکن را فقط در فایل محیطی محدودشده برنامه با مجوز فایل 600 قرار می‌دهد. مقدار توکن در خروجی لاگ یا مرورگر نمایش داده نمی‌شود.

اگر secret تنظیم نشده باشد، صفحه نسخه‌ها همچنان وضعیت نسخه و گزارش استقرار را نشان می‌دهد، اما دکمه شروع بروزرسانی غیرفعال خواهد بود.

## استفاده

از پنل مدیریت → مدیریت سامانه → نسخه‌ها و بروزرسانی:
1. «بررسی دوباره نسخه‌ها» را بزنید.
2. commit نصب‌شده و commit شاخه اصلی را مقایسه کنید.
3. مدیر ارشد «شروع بروزرسانی خودکار» را اجرا کند.
4. نتیجه نهایی را از لینک گزارش استقرار بازبینی کنید.

موفقیت درخواست dispatch به معنی موفقیت انتشار نیست؛ فقط پایان موفق گردش استقرار و بررسی سلامت دامنه، انتشار را موفق می‌کند.
