# قرارداد سرویس محتوای صفحه اصلی دیجی‌بایل پی

این سند قرارداد موردنیاز رابط صفحه اصلی در `web/template-v3.html` است. رابط کاربری به‌تنهایی مجوز مدیریت محتوا ایجاد نمی‌کند؛ تمام کنترل دسترسی و ذخیره‌سازی باید در سرور انجام شود.

## ۱. دریافت محتوای عمومی

`GET /api/v1/site-content/homepage`

پاسخ نمونه:

```json
{
  "data": {
    "hero": {
      "eyebrow": "متن بالای عنوان",
      "title": "عنوان صفحه اصلی",
      "description": "توضیحات بنر"
    },
    "features": {
      "feature1Title": "پرداخت آسان",
      "feature1Description": "توضیح مزیت"
    },
    "plans": {
      "title": "طرح‌های وام و خرید اقساطی",
      "description": "توضیح بخش"
    },
    "partners": {
      "title": "چرا دیجی‌بایل پی؟",
      "description": "توضیح بخش"
    },
    "how": {
      "title": "مراحل دریافت اعتبار",
      "description": "توضیح مراحل"
    },
    "trust": {
      "title": "امنیت و شفافیت",
      "description": "توضیح اعتماد"
    },
    "blog": {
      "title": "مجله دیجی‌بایل پی",
      "description": "راهنمای خرید و مدیریت مالی"
    },
    "newsletter": {
      "title": "تازه‌ها را از دست ندهید",
      "description": "خبرنامه"
    },
    "cta": {
      "title": "آماده‌اید؟",
      "description": "دعوت به عضویت"
    },
    "footer": {
      "description": "معرفی کوتاه در فوتر"
    }
  }

```

کلیدهای قابل ویرایش در DOM با `data-cms-section` و `data-cms-field` مشخص شده‌اند. متن خروجی باید به‌صورت متن امن (نه HTML خام) ذخیره و برگردانده شود.

## ۲. ذخیره تغییرات توسط مدیر

`PUT /api/v1/admin/site-content/homepage`

درخواست:

```json
{
  "section": "hero",
  "content": {
    "eyebrow": "متن بالای عنوان",
    "title": "عنوان جدید",
    "description": "توضیحات جدید"
  }
}
```

الزامات امنیتی غیرقابل‌چشم‌پوشی:
- احراز هویت سمت سرور و بررسی نقش/مجوز مدیر در هر درخواست؛ مخفی‌کردن دکمه در مرورگر کنترل امنیتی نیست.
- رد درخواست کاربر عادی با `403`، حتی اگر مستقیماً endpoint را فراخوانی کند.
- استفاده از نشست امن HttpOnly یا توکن معتبر؛ عدم اعتماد به نقش ارسالی از مرورگر.
- اعتبارسنجی نام بخش و کلیدهای مجاز، محدودیت طول متن، ثبت audit log شامل شناسه مدیر، زمان و تغییرات.
- محافظت CSRF در صورت استفاده از cookie session.
- ذخیره در دیتابیس پایدار؛ نه localStorage و نه فایل موقت مرورگر.
- پاسخ موفق با محتوای نهایی ذخیره‌شده در `data`.

## ۳. خبرنامه

`POST /api/v1/newsletter/subscribe`

درخواست: `{"email":"person@example.com","source":"homepage"}`

سرور باید ایمیل را اعتبارسنجی کند، عضویت تکراری را idempotent مدیریت کند، رضایت و زمان ثبت را ذخیره کند، محدودیت نرخ و تأیید ایمیل را پشتیبانی کند و پیام موفقیت/خطای فارسی برگرداند. اطلاعات خبرنامه نباید برای ارسال تبلیغات بدون رضایت استفاده شود.

## ۴. وبلاگ و خبرها

`GET /api/v1/blog/posts?status=published&limit=3`

پاسخ: آرایه‌ای از مطالب منتشرشده با فیلدهای `id`, `slug`, `title`, `excerpt`, `publishedAt` و در صورت نیاز `coverImage`. فقط محتوای منتشرشده برای عموم بازگردد. پنل مدیریت مطالب، وضعیت پیش‌نویس/انتشار و تاریخ انتشار باید سمت سرور کنترل شود.

## ۵. طرح‌ها و ماشین‌حساب

طرح‌ها و نرخ‌ها همچنان از سرویس فعلی `GET /api/v1/loan-products` می‌آیند. ویرایش محتوای ظاهری صفحه نباید نرخ، کارمزد، شرایط اعتبار یا داده مالی طرح را تغییر دهد. تغییرات مالی فقط از گردش‌کار مدیریت طرح و مجوزهای موجود انجام شود.

## ۶. مجوزها و نشان‌ها در فوتر

جایگاه‌های نماد اعتماد، ساماندهی و سایر مجوزها فعلاً placeholder هستند. فقط تصویر رسمی، شناسه/پیوند استعلام معتبر و تاریخ اعتبار تأییدشده باید از تنظیمات مدیریتی نمایش داده شود. هیچ نماد یا مجوز نمونه‌ای نباید به‌عنوان مجوز واقعی نمایش داده شود.

## وضعیت پیاده‌سازی

قالب صفحه اصلی اکنون رابط ویرایش درون‌صفحه‌ای مدیر، دریافت محتوای عمومی، فرم خبرنامه و بارگذاری فهرست وبلاگ را به این قرارداد متصل می‌کند. تا زمانی که endpointهای بالا در backend پیاده‌سازی و تست نشده‌اند، ذخیره محتوا، ثبت خبرنامه و فهرست وبلاگ در محیط production کامل محسوب نمی‌شوند؛ رابط کاربری نباید موفقیت ساختگی نشان دهد.
