# دیجی‌بایل | برنامه متصل به MariaDB واحد

این مخزن شامل رابط فارسی، API و ماژول‌های عملیاتی دیجی‌بایل است. پایگاه دادهٔ اجرایی برنامه فقط **MariaDB موجود روی سرور DirectAdmin** است؛ PostgreSQL در اجرای روزمرهٔ برنامه استفاده نمی‌شود.

## اجزای اجرا

- Node.js 22+
- MariaDB موجود روی سرور، از طریق Unix socket
- Next.js و API داخلی روی پورت `1631`
- ورود با رمز، کپچای سمت سرور، ثبت‌نام و OTP، نقش‌ها، ثبت رخدادهای امنیتی و مدیریت کاربران

## تنظیمات محرمانه

فایل `.env` را از روی `.env.example` بسازید و اطلاعات اتصال **همان دیتابیس موجود** را قرار دهید. رمز واقعی را داخل مخزن Git قرار ندهید. فایل باید مجوز `600` داشته باشد.

برنامه از این متغیرها استفاده می‌کند: `MARIADB_DATABASE`، `MARIADB_USER`، `MARIADB_PASSWORD`، `MARIADB_SOCKET` و `MARIADB_SOCKET_GID`.

هیچ `DATABASE_URL` یا متغیر `POSTGRES_*` برای اجرای برنامه لازم نیست.

## پشتیبان‌گیری

پیش از به‌روزرسانی یا تغییر ساختار:

```sh
bash scripts/backup-db.sh
```

این دستور از دیتابیس MariaDB پشتیبان فشرده می‌گیرد، صحت فایل gzip را بررسی می‌کند و SHA-256 آن را ثبت می‌کند. فایل‌های پشتیبان با مجوز محدود نگهداری می‌شوند.

## اجرا

```sh
docker compose config -q
docker compose build
docker compose up -d
docker compose ps
curl -fsS http://127.0.0.1:1631/healthz
```

هنگام شروع برنامه، جدول‌های مخصوص خود برنامه به‌صورت idempotent در MariaDB ایجاد می‌شوند. جدول‌های موجود ASP.NET، VamCity، BluVam و داده‌های عملیاتی قدیمی حذف یا بازنویسی نمی‌شوند.

## انتقال نهایی اطلاعات قدیمی

ابزار انتقال یک‌باره در پوشهٔ مستقل `scripts/migration-tools` قرار می‌گیرد و وابستگی موقت خواندن منبع قدیمی فقط در همان ابزار جداگانه نصب می‌شود؛ این وابستگی وارد `package.json` برنامه و تصویر Docker اجرایی نمی‌شود. انتقال باید با پشتیبان معتبر، تطبیق دقیق تعداد رکوردها و آزمون ورود و نقش‌ها انجام شود. هیچ Volume یا جدول منبعی پیش از تأیید این کنترل‌ها حذف نمی‌شود.

## آزمون

```sh
npm test
npm run build
```

GitHub Actions نیز آزمون‌ها، ساخت رابط و ساخت تصویر Docker را با MariaDB انجام می‌دهد.

## پیامک و امنیت

برای ارسال OTP واقعی، `KAVENEGAR_API_KEY` و `KAVENEGAR_TEMPLATE` را در فایل محرمانه `.env` تنظیم کنید. اگر فراهم‌کننده تنظیم نشده باشد، ارسال OTP به‌صورت fail-closed غیرفعال است و کد ساختگی صادر نمی‌شود.

OCR مدارک تا اتصال ارائه‌دهندهٔ معتبر، عمداً فعال اعلام نمی‌شود.
